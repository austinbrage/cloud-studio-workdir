# Create an IAM User with Specific Resource Permissions

![Terraform](https://img.shields.io/badge/Terraform-%235835CC.svg?style=for-the-badge&logo=terraform&logoColor=white)
![AWS](https://img.shields.io/badge/AWS-%23FF9900.svg?style=for-the-badge&logo=amazon-aws&logoColor=white)

This Terraform project creates an IAM user in AWS with **custom permissions** tailored to specific resources, rather than granting full administrative access. It is ideal for implementing the **principle of least privilege**, ensuring that users only have the permissions necessary for their specific tasks.

The purpose of this project is to automate the creation of IAM users with **fine-grained access control** to AWS resources. By defining custom policies, you can restrict access to only the services and actions required, enhancing security and compliance. For example, for users that generates credentials for a `Github Actions Workflow`.


## To be considered

This Terraform script is designed to be executed using the credentials of the AWS **root user** or an IAM user with **AdministratorAccess** permissions. These type of users are required because they have the necessary permissions to create an IAM user.

- **Important**: If using the root user, after running this script, it is highly recommended to deactivate the root user credentials and transition to using the newly created IAM user or another IAM user with appropriate permissions for ongoing management. This aligns with AWS security best practices.

## Password Management

After the Terraform script creates the new IAM user, it generates a secure password for console access. However, for security reasons, you should immediately change this auto-generated password in the AWS console. Below are the steps to reset the password:

1. On the IAM console of the ROOT USER, go to **Users** and select the created user.
2. Navigate to the **Security credentials** tab.
3. Under **Console sign-in**, click on **Manage console access**.
4. On the **Reset password** page, click on **Custom password**, type a new one, and confirm.

To retrieve the initial password generated by Terraform, use the following command since the output is set with `sensitive = true`:
```bash
terraform output -raw password
```

## Key Features

- **Custom Policies**: Define fine-grained permissions for specific AWS resources.
- **Least Privilege**: Ensures users only have the permissions they need.
- **Reusable Module**: The policy creation and attachment logic is encapsulated in a reusable module.
- **Default Tags**: Automatically applies consistent tags to all resources for better organization and cost tracking.

## Default Policies

By default, the project includes a **custom policy** that grants access to specific resources. For example:

1. **Amazon S3**: Access to a specific bucket for listing, reading, and writing objects.
2. **Amazon EC2**: Permissions to describe, start, and stop instances.

## Common Services and Example Policies

Here are examples of how you can grant permissions to other common AWS services:

### 1. **Amazon Lambda**
Allows invoking specific Lambda functions.

```hcl
policy_statements = [
  {
    effect    = "Allow"
    actions   = ["lambda:InvokeFunction"]
    resources = ["arn:aws:lambda:us-east-1:123456789012:function:my-function"]
  }
]
```

### 2. **Amazon RDS**
Allows describing and managing RDS instances.

```hcl
policy_statements = [
  {
    effect    = "Allow"
    actions   = ["rds:DescribeDBInstances", "rds:StartDBInstance", "rds:StopDBInstance"]
    resources = ["*"]
  }
]
```

### 3. **Amazon DynamoDB**
Allows reading and writing to a specific DynamoDB table.

```hcl
policy_statements = [
  {
    effect    = "Allow"
    actions   = ["dynamodb:GetItem", "dynamodb:PutItem"]
    resources = ["arn:aws:dynamodb:us-east-1:123456789012:table/my-table"]
  }
]
```
